# Dépôt

* [Repository](repository.md) - Dépôt GitHub et services rattachés, gérés par l'agent via leurs API ; documentation du dépôt (README.md, README.dev.md).
* [Signature des commits](signature-des-commits.md) - Commits signés et vérifiés, vérification sur GitHub seulement ; s'applique à tout commit.
* [Configuration du repository GitHub](configuration-du-repository-github.md) - Réglages du dépôt GitHub, Ruleset de main, sécurité du dépôt, GitHub Pages, merge fait par l'agent au nom de l'utilisateur, jamais par un collaborateur ; à lire pour toute modification de la configuration GitHub.
* [Intégration continue (CI)](integration-continue-ci.md) - Workflows CI, tests et images selon ce que modifie la Pull Request, aucun check sur une Pull Request en conflit avec sa branche de destination, checks requis tenus alignés sur le Ruleset, secrets, quotas de Docker Hub et de l'API GitHub consommés par chaque push, échec d'un service extérieur imputé à un quota sur des faits seulement, sinon refus ponctuel relancé aussitôt.
* [Analyse de la qualité du code](analyse-de-la-qualite-du-code.md) - Analyse SonarQube Cloud : workflow, porte de qualité, jetons, périmètre et exclusions, nouveau code ; à lire pour modifier l'analyse ou sa configuration.
* [Mises à jour des dépendances](mises-a-jour-des-dependances.md) - Versions épinglées, relevé des versions, vulnérabilités connues, montées et leur revue de l'existant ; à lire quand le relevé est dû ou pour toute montée de version.
* [Contrôle qualité hebdomadaire](controle-qualite-hebdomadaire.md) - Contrôle hebdomadaire du code global de main (SonarQube Cloud, règles de style, tests de mutation), rien de bloquant, ticket de suivi de la dette qualité par urgence (critique, prioritaire, au fil de l'eau), point à corriger ou non pertinent, traitement borné à une Pull Request par semaine ; à lire quand le traitement est dû ou pour modifier le contrôle.
* [Traitement du contrôle qualité à la reprise du travail](traitement-du-controle-qualite-a-la-reprise-du-travail.md) - À chaque reprise du travail, avec le relevé des versions : quand le traitement des entrées du contrôle qualité est dû, qui le vérifie et où sa trace se lit ; s'il est dû, lire Contrôle qualité hebdomadaire.
* [Relevé des versions à la reprise du travail](releve-des-versions-a-la-reprise-du-travail.md) - À chaque reprise du travail : quand le relevé des versions est dû, qui le vérifie et où sa trace se lit ; s'il est dû, lire Mises à jour des dépendances.
* [Règle absolue : interdiction de pousser directement sur `main`](regle-absolue-interdiction-de-pousser-directement-sur-main.md) - Interdiction de commiter ou pousser sur main : toute modification passe par une Pull Request.
* [Stratégie de branches](strategie-de-branches.md) - Modèle trunk-based, branche de release créée au besoin seulement, pour un correctif d'une version dépassée, branches persistantes (main et branches de release seules), nommage des branches (feat/, fix/, chore/), branche de travail tenue à jour de sa branche de destination.
* [Conventions de commit](conventions-de-commit.md) - Conventional Commits pour les commits et titres de PR, description de PR devenue corps du commit squashé, template de PR, lu dans le dépôt public Tetram76/.github sans jamais le rattacher à la session.
* [Versions et releases](versions-et-releases.md) - Numérotation semver, jalons, rattachement des tickets et PR, version publiable signalée à l'utilisateur, publication sur sa seule décision, menée par l'agent (tag, release, analyse, images), version 0 annoncée par les notes de sa release, paquet de déploiement joint à la release.
