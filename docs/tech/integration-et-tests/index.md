# Intégration continue et tests

* [Intégration continue](integration-continue.md) - Cette page explique ce qu'exécute le workflow CI à chaque Pull Request et sur main, comment il choisit les étapes à exécuter d'après les fichiers modifiés, et ce que fait chacun de ses jobs ; à lire pour comprendre un check, un échec du CI ou ce qu'exécutera une Pull Request.
* [Stratégie de tests](strategie-de-tests.md) - Cette page explique comment les tests sont organisés en projets, ce dont chacun a besoin pour s'exécuter, et ce qui les rend indépendants de l'heure et du thème tiré au hasard ; à lire pour écrire un test, choisir son projet ou comprendre l'échec d'un test ou d'une capture de référence.
* [Contrôles périodiques](controles-periodiques.md) - Cette page explique les deux contrôles planifiés de main, le contrôle qualité hebdomadaire et le contrôle de sécurité quotidien, comment ils tiennent leur ticket de suivi et quand ils échouent, ainsi que le relevé des versions que mène l'agent et les scripts qui relient la dette au fil de l'eau à la branche d'un chantier ; à lire pour comprendre un échec de ces contrôles, une entrée de leur ticket, ou modifier ce qu'ils relèvent.
